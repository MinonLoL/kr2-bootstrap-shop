## Описание проекта

**Goldabook** — современный адаптивный сайт литературного сообщества и книжного клуба. Проект разработан на **HTML5**, **CSS3** и **Bootstrap 5.3**. Он помогает любителям чтения находить выдающиеся книги по жанрам и рейтингу читателей, знакомиться с отзывами резидентов клуба, изучать план дискуссий и записываться на регулярные очные и онлайн-встречи.

### Основные разделы сайта:
1. **Главная (`index.html`)** — представление клуба, ценности и миссия, интерактивная карусель подборки месяца, карточки ближайших митапов и отзывы участников.
2. **Каталог книг (`catalog.html`)** — адаптивная 12-колоночная сетка карточек книг с панелью поиска, фильтрацией по жанрам, сортировкой по рейтингу и пагинацией.
3. **Карточка книги (`product.html`)** — детальное описание романа «Мастер и Маргарита», обложка, рейтинг, интерактивные вкладки (темы дискуссии, отзывы читателей, цитаты), таблица характеристик издания и блок частых вопросов (Accordion).
4. **Встречи клуба и запись (`order.html`)** — подробный календарь событий и полноценная форма записи на литературные встречи со всеми валидируемыми полями.
5. **Контакты (`contacts.html`)** — адрес лофта читальни на Покровке, часы работы, интерактивная карта, ссылки на соцсети, форма обратной связи и FAQ клуба.
6. **Встречи (`meetings.html`)** — быстрый алиас/редирект для раздела встреч.

## Используемые технологии
- **HTML5:** семантическая структура (`header`, `nav`, `main`, `section`, `article`, `footer`, `blockquote`).
- **Bootstrap 5.3.3:** 12-колоночная сетка, utility-классы и интерактивные JS-компоненты.
- **CSS3 / `custom.css`:** стилизация фирменной палитры (глубокий грифельный, золотой янтарь), стили доступности (`:focus-visible`, `skip-link`), плавные hover-эффекты карточек.
- **Векторная графика (SVG):** локальный набор чётких векторных обложек книг, логотипа клуба, аватаров резидентов и иллюстраций в папке `images/`.
- **Git & GitHub:** контроль версий, ветки, фиксация этапов разработки и Pull Request.

## Способ подключения Bootstrap (Выполнение повышенного требования)

В соответствии с **пунктом 11 и критерием 14.3 методических указаний**, в проекте выполнено дополнительное задание: **Bootstrap подключён локально, без опоры на сторонние CDN**.

Файлы фреймворка размещены внутри репозитория в папке `vendor/bootstrap/`:
- `vendor/bootstrap/css/bootstrap.min.css` — скомпилированные и минифицированные стили Bootstrap 5.3.3;
- `vendor/bootstrap/js/bootstrap.bundle.min.js` — скомпилированный скрипт интерактивных компонентов Bootstrap (включая Popper.js).

### Порядок подключения в `<head>`:
```html
<!-- 1. Локальные стили фреймворка Bootstrap -->
<link rel="stylesheet" href="vendor/bootstrap/css/bootstrap.min.css">

<!-- 2. Собственные переопределения и стили проекта (строго ПОСЛЕ Bootstrap) -->
<link rel="stylesheet" href="css/custom.css">
```

### Подключение скриптов перед `</body>`:
```html
<!-- Интерактивный Bootstrap JS Bundle -->
<script src="vendor/bootstrap/js/bootstrap.bundle.min.js"></script>
```

Такой способ гарантирует полную автономность проекта, независимость от сетевых сбоев и высокую скорость загрузки страниц.

## Реализованные компоненты Bootstrap

## Проверка адаптивности

Страницы проверены через браузерные инструменты разработчика (DevTools):
- **Мобильные устройства (360–430px):** элементы перестраиваются в 1 колонку (`col-12`), меню складывается в гамбургер, формы и модальные окна не выходят за ширину экрана, горизонтальная прокрутка отсутствует.
- **Планшеты (768px):** сетка переходит в двухколоночный режим (`col-md-6`), навигация остаётся компактной.
- **Десктоп (1024–1440px):** трёхколоночная сетка каталога (`col-lg-4`), полноразмерный navbar, развёрнутые hero-блоки.

## Ответы на контрольные вопросы (Раздел 15)

1. **Почему КР №2 выполняется в отдельном репозитории?**  
   Для изолированной демонстрации навыков работы с CSS-фреймворком Bootstrap, сохранения чистой истории коммитов и разделения подходов чистой вёрстки (КР №1) и компонентной фреймворк-разработки.
2. **Почему КР №2 не является адаптацией КР №1?**  
   КР №2 — это новая независимая реализация предметной области на готовой 12-колоночной сетке и готовых классах компонентов Bootstrap, а не ручная доработка старых стилей.
3. **Что такое CSS-фреймворк?**  
   Это библиотека предварительно подготовленных CSS-правил, сеток, утилит и компонентов, ускоряющая разработку адаптивных интерфейсов.
4. **Для чего используется `container`?**  
   Ограничивает максимальную ширину контента в зависимости от брейкпоинта и центрирует его по горизонтали с внутренними боковыми отступами.
5. **Для чего используется `row`?**  
   Создаёт строчный флекс-контейнер для колонок `col-*`, компенсируя их боковые отступы отрицательными margins.
6. **Для чего используются `col-*`?**  
   Определяют долю ширины, которую занимает элемент в 12-колоночной системе на разных экранах (`col-12`, `col-md-6`, `col-lg-4`).
7. **Для чего используются `g-*`, `gx-*`, `gy-*`?**  
   Управляют промежутками (gutters) между колонками по горизонтали (`gx-`), вертикали (`gy-`) или обеим осям (`g-`).
8. **Почему для мобильного меню и модальных окон нужен Bootstrap JS Bundle?**  
   Потому что они используют JavaScript (и библиотеку позиционирования Popper) для управления классами показа/скрытия (`collapse`, `modal`, `dropdown`) и атрибутами доступности `aria-expanded`.
9. **Почему `custom.css` должен подключаться после Bootstrap?**  
   В каскадной таблице стилей (CSS) правила, расположенные ниже, имеют приоритет при равной специфичности селекторов, что позволяет переопределять стандартные свойства Bootstrap.
10. **Чем отличается локальное подключение от CDN?**  
    Локальное подключение хранит файлы внутри проекта, гарантируя работоспособность без интернета, отсутствие риска блокировок CDN-серверов и неизменность версии библиотеки.
